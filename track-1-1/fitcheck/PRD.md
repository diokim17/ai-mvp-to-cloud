# FitCheck PRD

> 채용공고와 내 이력서(PDF)를 비교해 적합도 점수, 부족한 역량, 이력서 문장 수정안을 알려 주는 AI 웹 서비스
>
> - 문서 버전: v0.1 (초안)
> - 작성일: 2026-10-20
> - 개발 기간: 1주 (이번 주 내 MVP 개발 및 배포)
> - 서비스명 `FitCheck`는 임시 이름이며 변경 가능합니다.

---

# 1. Product Summary

**FitCheck**는 구직자가 지원하려는 **채용공고 링크**와 **이력서 PDF**를 올리면, AI가 두 문서를 비교해 다음 세 가지를 알려 주는 웹 서비스입니다.

1. **적합도 점수 (0~100점)**: 공개된 채점 기준표에 따라 항목별 점수와 합계를 제시합니다.
2. **부족한 역량 목록**: 공고가 요구하지만 이력서에서 확인되지 않는 역량과 보완 방법을 알려 줍니다.
3. **이력서 문장 수정안**: 공고에 맞춰 이력서 문장을 어떻게 고치면 좋을지 "원문 → 수정안 → 이유" 형식으로 제시합니다.

**사용 방식**
- 사용자가 공고 링크를 붙여넣으면 서버가 공고 페이지를 읽어 옵니다.
- 읽어 온 내용이 맞는지 사용자가 미리보기로 확인합니다.
- 공고 페이지를 읽지 못하면(접속 차단, 로그인 필요 등) 사용자에게 알리고 **공고 화면 캡처 이미지**를 요청합니다.
- 이력서는 **PDF 파일 첨부**로 받습니다.
- 분석 결과는 계정에 저장되어 언제든 다시 볼 수 있습니다.

# 2. Target User

| 그룹 | 특징 | 사용 목적 | 필요한 기능 |
|---|---|---|---|
| **신입·주니어 구직자** (주 사용자) | 지원 경험이 적고, 이력서를 공고마다 어떻게 고쳐야 할지 모름 | 지원 전 내 이력서가 공고에 얼마나 맞는지, 무엇을 보완할지 확인 | 공고·이력서 입력, 적합도 점수, 부족 역량, 문장 수정안 |
| **경력 이직자** | 경력은 있지만 공고 키워드에 맞춰 경험을 표현하는 데 시간이 많이 듦 | 여러 공고에 빠르게 맞춤 이력서 작성 | 문장 수정안, 분석 기록 비교 |
| **비로그인 방문자** (포트폴리오 리뷰어·면접관 포함) | 가입 없이 서비스가 무엇인지 빠르게 파악하고 싶음 | 서비스 가치와 결과 화면 확인 | 랜딩 페이지의 샘플 분석 결과 |

**권한 구분**
- 비로그인 방문자: 랜딩 페이지와 샘플 결과만 볼 수 있습니다.
- 로그인 사용자: 분석 생성, 본인 분석 기록 조회·삭제가 가능합니다. 다른 사용자의 데이터는 볼 수 없습니다.

# 3. Problem

**사용자가 겪는 문제**
- 공고마다 요구 역량이 달라 이력서를 맞춤으로 고쳐야 하지만, 무엇이 부족하고 어디를 고쳐야 할지 스스로 판단하기 어렵습니다.
- 공고와 이력서를 나란히 놓고 한 줄씩 비교하는 데 공고 1건당 30분 이상 걸립니다(추정).
- 서류 탈락 이유를 알려 주지 않기 때문에 개선 방향을 알 수 없습니다.

**기존 해결 방식의 한계**

| 기존 방식 | 한계 |
|---|---|
| 직접 비교 | 시간이 오래 걸리고, 본인 이력서를 객관적으로 보기 어려움 |
| 지인·멘토 첨삭 | 매번 부탁하기 어렵고 답을 받기까지 시간이 걸림 |
| ChatGPT·Claude 같은 범용 AI 채팅 | 매번 공고와 이력서를 복사·붙여넣기 해야 하고, 결과 형식이 매번 달라 비교가 어려움. 공고 링크를 못 읽는 경우가 많음 |

**이 서비스로 해결해야 하는 이유**
- 링크와 PDF만 넣으면 되므로 입력이 간단합니다.
- 링크를 못 읽어도 캡처로 이어 갈 수 있어 중간에 막히지 않습니다.
- 결과가 항상 같은 형식(점수·부족 역량·수정안)으로 나와 공고끼리 비교할 수 있습니다.

# 4. Core Value

| 사용자 그룹 | 핵심 가치 | 이를 실현하는 기능 | 기대 효과 |
|---|---|---|---|
| 신입·주니어 구직자 | "무엇을 고쳐야 하는지"를 구체적으로 알 수 있음 | 부족 역량 목록, 문장 수정안 | 공고 1건 분석 시간 30분 이상 → 2분 이내(목표) |
| 경력 이직자 | 경험을 공고 언어로 빠르게 바꿀 수 있음 | 원문 → 수정안 → 이유 형식의 수정안, 분석 기록 | 맞춤 이력서 작성 시간 단축 |
| 비로그인 방문자 | 가입 없이 서비스 가치를 바로 이해 | 랜딩 페이지 샘플 결과 | 서비스 이해 및 가입 유도 |

**AI 결과 신뢰성 원칙**
- 점수는 공개된 채점 기준표에 따라 항목별로 매기고, 항목별 점수를 함께 보여 줍니다.
- "보유 역량"으로 판단한 항목에는 이력서의 근거 문장을 함께 표시합니다. 근거가 없으면 보유로 판단하지 않습니다.
- AI 응답은 정해진 JSON 형식으로만 받고, 형식이 맞지 않으면 다시 요청합니다.

# 6. User Scenario

### 시나리오 A. 신입 구직자 — 링크 읽기 성공

- **상황**: 프론트엔드 신입 김지원 씨가 원티드의 공고에 지원하려고 합니다.
- **목적**: 지원 전에 이력서에서 보완할 점을 알고 싶습니다.

1. FitCheck에 로그인하고 "새 분석"을 누릅니다.
2. 공고 링크를 붙여넣고 "공고 불러오기"를 누릅니다.
3. 화면에 공고 제목·회사명·요약이 표시되고, 맞는지 확인한 뒤 "맞아요"를 누릅니다.
4. 이력서 PDF를 첨부하고 "분석 시작"을 누릅니다.
5. 약 30초 뒤 결과 화면에서 적합도 72점, 부족 역량 "TypeScript 실무 경험", 수정안 3개를 확인합니다.
- **결과**: 수정안을 참고해 프로젝트 경험 문장을 고친 뒤 지원합니다.

### 시나리오 B. 경력 이직자 — 링크 읽기 실패 → 캡처

- **상황**: 백엔드 3년 차 이준호 씨가 로그인해야 보이는 공고에 지원하려고 합니다.

1. 공고 링크를 붙여넣고 "공고 불러오기"를 누릅니다.
2. "공고 내용을 읽지 못했습니다. 공고 화면을 캡처해서 올려 주세요" 안내가 나타납니다.
3. 공고 화면 캡처 3장을 업로드합니다.
4. 이력서 PDF를 첨부하고 "분석 시작"을 누릅니다.
5. 결과를 확인하고, 분석 기록에서 지난주 다른 공고의 결과와 점수를 비교합니다.
- **결과**: 점수가 더 높은 공고부터 지원하기로 합니다.

### 시나리오 C. 포트폴리오 리뷰어 — 비로그인 둘러보기

1. 포트폴리오에 있는 링크로 FitCheck 랜딩 페이지에 들어옵니다.
2. 서비스 소개와 샘플 분석 결과를 확인합니다.
- **결과**: 가입하지 않고도 서비스가 무엇을 하는지 파악합니다.

# 7. User Flow

```
[랜딩] ─ 비로그인 ─→ 샘플 결과 보기
   │
   └─ "시작하기" → [로그인/회원가입] → [분석 기록(홈)]
                                          │
                                   "새 분석" 클릭
                                          ▼
                     ┌──────── [새 분석: 1단계 공고 입력] ────────┐
                     │  링크 입력 → "공고 불러오기"                │
                     │      │                                     │
                     │   서버가 페이지 읽기 + AI 공고 판정          │
                     │      ├─ 성공 → 미리보기 표시                │
                     │      │     ├─ "맞아요" → 2단계              │
                     │      │     └─ "아니에요" → 캡처 입력으로 전환 │
                     │      └─ 실패 → 실패 안내 + 캡처 입력 표시     │
                     │                  └─ 캡처 1~5장 업로드 → 2단계 │
                     └───────────────────────────────────────────┘
                                          ▼
                     [새 분석: 2단계 이력서 PDF 첨부] → "분석 시작"
                                          ▼
                           분석 중(로딩, 최대 90초)
                             ├─ 성공 → [분석 결과]
                             └─ 실패 → 오류 안내 + "다시 시도"
```

**조건별 분기와 예외 처리**

| 상황 | 처리 결과 |
|---|---|
| URL 형식이 아님 (http/https 아님) | 입력란 아래 "올바른 링크를 입력해 주세요" 표시, 요청 보내지 않음 |
| 접속 오류·10초 초과·HTTP 오류(4xx, 5xx) | 링크 읽기 실패 → 캡처 요청 |
| HTML 페이지가 아님 (PDF·이미지 링크 등) | 링크 읽기 실패 → 캡처 요청 |
| 본문 글자 수 300자 미만 | 링크 읽기 실패 → 캡처 요청 (로그인·차단 화면으로 추정) |
| AI가 채용공고가 아니라고 판정 | 링크 읽기 실패 → 캡처 요청 |
| 사용자가 미리보기에서 "아니에요" 선택 | 캡처 입력으로 전환 |
| 캡처 형식·크기·개수 초과 | 해당 파일 업로드 거부 + 사유 안내 |
| PDF 형식 아님·5MB 초과·10페이지 초과·암호 걸림 | 업로드 거부 + 사유 안내 |
| 하루 분석 10회 초과 | "오늘 분석 횟수를 모두 사용했습니다" 안내, 분석 버튼 비활성화 |
| AI 응답 형식 오류 | 서버가 1회 자동 재시도, 그래도 실패하면 분석 실패 처리 |
| AI 호출 오류·시간 초과 | 분석 실패 처리, "다시 시도" 버튼 표시 (실패는 하루 횟수에서 차감하지 않음) |
| 로그인하지 않고 분석·기록 페이지 접근 | 로그인 화면으로 이동, 로그인 후 원래 페이지로 복귀 |

# 8. Screens

| ID | 화면 | 목적 | 접근 권한 |
|---|---|---|---|
| S1 | 랜딩 | 서비스 소개, 샘플 결과 | 모두 |
| S2 | 로그인·회원가입 | 계정 인증 | 비로그인 |
| S3 | 분석 기록 (홈) | 내 분석 목록 | 로그인 |
| S4 | 새 분석 | 공고 입력 → 이력서 첨부 → 분석 요청 | 로그인 |
| S5 | 분석 결과 | 분석 결과 상세 | 로그인 (본인 분석만) |

### S1. 랜딩
- **구성 요소**: 서비스 한 줄 소개, 사용 방법 3단계(링크 → PDF → 결과), 샘플 분석 결과 카드(점수·부족 역량·수정안 일부), "시작하기" 버튼
- **동작**: "시작하기" → 비로그인이면 S2, 로그인 상태면 S3
- **표시 조건**: 로그인 상태면 상단에 "내 분석 기록" 링크 표시

### S2. 로그인·회원가입
- **구성 요소**: 탭(로그인 / 회원가입), 이메일 입력, 비밀번호 입력, 제출 버튼, 오류 메시지 영역
- **동작**: 로그인 성공 → S3 (또는 원래 가려던 페이지), 회원가입 성공 → 바로 로그인 처리 후 S3
- **입력 검증**: 이메일 형식, 비밀번호 8자 이상

### S3. 분석 기록 (홈)
- **구성 요소**: "새 분석" 버튼, 오늘 남은 분석 횟수, 분석 카드 목록(회사명, 공고 제목, 적합도 점수, 분석 일시, 상태), 각 카드의 삭제 버튼
- **동작**: 카드 클릭 → S5, "새 분석" → S4, 삭제 → 확인 창 후 삭제
- **빈 상태**: "아직 분석 기록이 없습니다" + "새 분석" 버튼
- **정렬**: 최신순

### S4. 새 분석 (2단계 진행 표시)
- **1단계: 공고 입력**
  - 링크 입력란, "공고 불러오기" 버튼, 불러오는 중 표시
  - 성공 시 미리보기 카드(회사명, 공고 제목, 주요 요구사항 요약) + "맞아요" / "아니에요" 버튼
  - 실패 시 안내 문구 + 캡처 업로드 영역(끌어다 놓기, 썸네일 미리보기, 개별 삭제)
  - 미리보기 확인 또는 캡처 1장 이상 업로드 시 "다음" 활성화
- **2단계: 이력서 첨부**
  - PDF 업로드 영역, 첨부된 파일명·용량 표시, 파일 교체 버튼
  - 개인정보 안내: "이력서 파일은 분석 직후 삭제되며 분석 결과만 저장됩니다"
  - "분석 시작" 버튼 (PDF 첨부 + 남은 횟수 1 이상일 때 활성화)
- **분석 중**: 진행 표시와 "최대 1분 정도 걸릴 수 있어요" 문구, 중복 클릭 방지
- **완료 시**: S5로 이동

### S5. 분석 결과
- **구성 요소**
  - 상단: 회사명, 공고 제목, 공고 링크(링크로 입력한 경우), 분석 일시
  - 적합도 점수(큰 숫자 + 원형 게이지) + 한 줄 총평
  - 항목별 점수 막대(필수 자격, 우대 사항, 직무 경험, 표현·구성)
  - 보유 역량 목록(역량 + 이력서 근거 문장)
  - 부족 역량 목록(역량, 필수/우대 구분, 보완 방법)
  - 문장 수정안 카드(원문 → 수정안 → 이유, 수정안 복사 버튼)
- **동작**: "목록으로" → S3, "새 분석" → S4, 삭제 → 확인 후 삭제하고 S3로 이동
- **권한**: 다른 사용자의 분석 ID로 접근하면 "분석을 찾을 수 없습니다" 표시

# 9. Functional Requirements

### 인증 (AUTH)

| ID | 요구사항 |
|---|---|
| FR-AUTH-01 | 사용자는 이메일과 비밀번호(8자 이상)로 회원가입할 수 있다. 이미 가입된 이메일이면 오류를 표시한다. |
| FR-AUTH-02 | 사용자는 이메일과 비밀번호로 로그인할 수 있다. 실패 시 "이메일 또는 비밀번호가 올바르지 않습니다"를 표시한다. |
| FR-AUTH-03 | 사용자는 로그아웃할 수 있다. |
| FR-AUTH-04 | 로그인하지 않은 사용자가 S3·S4·S5에 접근하면 S2로 이동시키고, 로그인 후 원래 페이지로 돌려보낸다. |

### 공고 입력 (JOB)

| ID | 요구사항 |
|---|---|
| FR-JOB-01 | 사용자가 입력한 URL이 `http://` 또는 `https://`로 시작하는 올바른 형식인지 브라우저에서 먼저 검사한다. |
| FR-JOB-02 | 서버(Edge Function `fetch-job-posting`)는 URL 페이지를 1회 요청한다. 제한 시간 10초, 응답 크기 2MB, 리다이렉트 최대 3회. |
| FR-JOB-03 | 서버는 내부망 주소(localhost, 사설 IP 대역, 클라우드 메타데이터 주소)로의 요청을 거부한다. (SSRF 방지: 서버를 이용해 내부 시스템에 접근하는 공격을 막는 조치) |
| FR-JOB-04 | 서버는 HTML에서 스크립트·스타일 등을 제거하고 본문 텍스트를 추출한다. 20,000자를 넘으면 앞부분 20,000자만 사용한다. |
| FR-JOB-05 | 다음 중 하나라도 해당하면 `실패`로 응답한다: 접속 오류·시간 초과, HTTP 상태 400 이상, HTML이 아닌 응답, 본문 300자 미만, AI 판정 결과 채용공고 아님. 실패 응답에는 사유 코드를 포함한다. |
| FR-JOB-06 | 서버는 추출한 텍스트를 경량 AI 모델(Claude Haiku)에 보내 ① 채용공고 여부 ② 회사명 ③ 공고 제목 ④ 주요 요구사항 요약을 JSON으로 받는다. |
| FR-JOB-07 | 성공 시 미리보기를 표시하고, 사용자가 "맞아요"를 누르면 공고 텍스트를 분석 입력으로 확정한다. "아니에요"를 누르면 캡처 입력으로 전환한다. |
| FR-JOB-08 | 실패 시 "공고 내용을 읽지 못했습니다. 공고 화면을 캡처해서 올려 주세요"를 표시하고 캡처 업로드 영역을 보여 준다. |
| FR-JOB-09 | 캡처는 PNG·JPG·WebP만, 최대 5장, 장당 3MB 이하로 받는다. 조건에 맞지 않는 파일은 거부하고 사유를 표시한다. |

### 이력서 (RES)

| ID | 요구사항 |
|---|---|
| FR-RES-01 | 이력서는 PDF 1개만 받는다. 파일 형식(확장자와 MIME 타입)과 크기(5MB 이하)를 브라우저에서 먼저 검사한다. |
| FR-RES-02 | 서버는 PDF의 페이지 수(10페이지 이하)와 암호 설정 여부를 확인하고, 조건에 맞지 않으면 분석을 거부한다. |
| FR-RES-03 | 업로드 파일(이력서·캡처)은 Supabase Storage의 비공개 버킷 `uploads/{user_id}/{analysis_id}/`에 저장한다. 본인만 업로드·조회할 수 있다. |

### AI 분석 (AI)

| ID | 요구사항 |
|---|---|
| FR-AI-01 | "분석 시작" 시 `analyses` 레코드를 `processing` 상태로 만들고 Edge Function `analyze-match`를 호출한다. |
| FR-AI-02 | 서버는 하루 분석 횟수(성공 + 진행 중, 한국 시간 기준 자정 초기화)가 10회 이상이면 분석을 거부한다. |
| FR-AI-03 | 서버는 이력서 PDF와 공고(텍스트 또는 캡처 이미지)를 Claude Sonnet에 함께 보내고, 정해진 JSON 형식(11장의 `result` 구조)으로만 응답받는다. |
| FR-AI-04 | 채점 기준표: 필수 자격 50점, 우대 사항 20점, 직무 경험 연관성 20점, 이력서 표현·구성 10점, 합계 100점. 이 기준을 프롬프트에 명시한다. |
| FR-AI-05 | 보유 역량에는 이력서 원문의 근거 문장을 반드시 포함한다. 근거 문장을 찾을 수 없는 역량은 보유 역량으로 판단하지 않는다. |
| FR-AI-06 | 문장 수정안은 3~5개, 각 항목은 원문·수정안·이유로 구성한다. 이력서에 없는 경험을 지어내지 않는다. |
| FR-AI-07 | 서버는 응답 JSON을 검증한다(필수 필드, 점수 범위 0~100, 항목별 점수 합 = 총점). 검증 실패 시 1회 재시도하고, 다시 실패하면 `failed` 처리한다. |
| FR-AI-08 | 캡처로 입력한 경우, AI 응답에 회사명·공고 제목을 함께 받아 저장한다. |
| FR-AI-09 | 분석이 끝나면(성공·실패 모두) Storage의 업로드 파일을 삭제한다. 삭제 실패는 서버 로그에 기록한다. |
| FR-AI-10 | 실패 시 `analyses.status`를 `failed`로, `error_code`에 사유를 저장하고 사용자에게 "분석에 실패했습니다. 다시 시도해 주세요"를 표시한다. |

# 10. Acceptance Criteria

### 인증
- [ ] 새 이메일과 8자 이상 비밀번호로 회원가입하면 S3로 이동한다.
- [ ] 이미 가입된 이메일로 회원가입하면 오류 문구가 표시된다.
- [ ] 비밀번호를 틀리면 로그인되지 않고 오류 문구가 표시된다.
- [ ] 로그아웃 상태에서 S4 주소로 직접 접근하면 S2로 이동하고, 로그인 후 S4로 돌아온다.

### 공고 입력
- [ ] 정상 공개 공고 링크를 넣으면 10초 이내에 회사명·제목·요약 미리보기가 표시된다.
- [ ] `abc` 같은 잘못된 형식을 넣으면 서버 요청 없이 형식 오류가 표시된다.
- [ ] 존재하지 않는 주소, 로그인이 필요한 페이지, 채용공고가 아닌 페이지(예: 뉴스 기사)를 넣으면 실패 안내와 캡처 업로드 영역이 표시된다.
- [ ] `http://localhost`, `http://127.0.0.1`, `http://169.254.169.254`를 넣으면 서버가 요청을 거부한다.
- [ ] 미리보기에서 "아니에요"를 누르면 캡처 업로드 영역으로 바뀐다.
- [ ] 캡처 6장째, 3MB 초과 파일, GIF 파일은 업로드가 거부되고 사유가 표시된다.

### 이력서
- [ ] 5MB 이하 PDF는 첨부되고 파일명·용량이 표시된다.
- [ ] PDF가 아닌 파일, 5MB 초과 PDF는 첨부가 거부된다.
- [ ] 10페이지 초과 PDF, 암호 걸린 PDF는 분석 요청 시 거부되고 사유가 표시된다.

### AI 분석
- [ ] 링크 입력과 캡처 입력 각각에서 분석이 90초 이내에 끝나고 S5가 표시된다.
- [ ] 결과의 항목별 점수 합이 총점과 같고, 총점이 0~100 범위다.
- [ ] 보유 역량마다 이력서 근거 문장이 표시되며, 그 문장이 실제 이력서에 있다(샘플 이력서 3종으로 수동 확인).
- [ ] 문장 수정안이 3~5개이고, 각 항목에 원문·수정안·이유가 있다.
- [ ] 분석 완료 후 Storage에 해당 분석의 업로드 파일이 남아 있지 않다(성공·실패 모두).
- [ ] 같은 계정으로 하루 11번째 분석을 요청하면 거부되고, 실패한 분석은 횟수에 포함되지 않는다.
- [ ] Claude API 호출이 실패하도록 만든 경우(잘못된 키 등) 분석이 `failed`가 되고 "다시 시도" 버튼이 표시된다.

### 권한·데이터
- [ ] 사용자 A가 사용자 B의 분석 ID로 S5에 접근하면 "분석을 찾을 수 없습니다"가 표시된다.
- [ ] 사용자 A가 Supabase 클라이언트로 B의 `analyses` 행이나 Storage 파일을 조회·삭제하려 하면 실패한다.
- [ ] 배포된 브라우저 코드(번들)에서 Claude API Key 문자열이 발견되지 않는다.
- [ ] 분석 삭제 후 S3 목록과 DB에서 해당 분석이 사라진다.

# 11. Data Requirements

### 테이블: `analyses`

| 필드명 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `id` | `uuid` | Y | 기본 키, 기본값 `gen_random_uuid()` |
| `user_id` | `uuid` | Y | `auth.users.id` 참조, 사용자 삭제 시 함께 삭제 |
| `job_source` | `text` | Y | `url` 또는 `screenshot` |
| `job_url` | `text` | N | 링크로 입력한 경우 공고 URL |
| `job_text` | `text` | N | 링크에서 추출한 공고 본문 (최대 20,000자) |
| `company_name` | `text` | N | 회사명 |
| `job_title` | `text` | N | 공고 제목 |
| `resume_file_name` | `text` | Y | 업로드한 이력서 파일명 (원본 파일은 삭제됨) |
| `status` | `text` | Y | `processing`, `completed`, `failed` 중 하나 |
| `match_score` | `smallint` | N | 적합도 총점 0~100 (`completed`일 때 필수) |
| `result` | `jsonb` | N | AI 분석 결과 (아래 구조) |
| `error_code` | `text` | N | 실패 사유 코드 |
| `model` | `text` | N | 분석에 사용한 AI 모델 ID |
| `created_at` | `timestamptz` | Y | 생성 시각, 기본값 `now()` |
| `updated_at` | `timestamptz` | Y | 수정 시각 |

**제약 조건**
- `job_source = 'url'`이면 `job_url`과 `job_text`는 필수입니다.
- `match_score`는 0 이상 100 이하입니다.
- 하루 횟수 계산을 위해 `(user_id, created_at)`에 인덱스를 둡니다.

### `result` JSON 구조

```json
{
  "summary": "한 줄 총평",
  "match_score": 72,
  "score_breakdown": {
    "required_qualifications": 35,
    "preferred_qualifications": 12,
    "experience_relevance": 17,
    "presentation": 8
  },
  "matched_skills": [
    { "skill": "React", "evidence": "이력서 원문 근거 문장" }
  ],
  "missing_skills": [
    { "skill": "TypeScript 실무 경험", "importance": "required", "suggestion": "보완 방법" }
  ],
  "resume_suggestions": [
    { "original": "원문 문장", "revised": "수정안", "reason": "수정 이유" }
  ]
}
```

- `score_breakdown` 항목별 최대 점수: 50 / 20 / 20 / 10
- `importance`: `required`(필수) 또는 `preferred`(우대)
- `resume_suggestions`: 3~5개

### 파일 저장소: Supabase Storage 버킷 `uploads` (비공개)

- 경로: `{user_id}/{analysis_id}/resume.pdf`, `{user_id}/{analysis_id}/job_1.png` …
- 분석이 끝나면 즉시 삭제하는 임시 보관 용도입니다.

### 관계

```
auth.users (1) ──< analyses (N)
analyses (1) ──< uploads 버킷의 파일 (N, 임시)
```

### 접근 권한 규칙 (RLS)

| 대상 | 조회 | 생성 | 수정 | 삭제 |
|---|---|---|---|---|
| `analyses` | 본인 행만 (`user_id = auth.uid()`) | 본인 `user_id`로만, `status = 'processing'`으로만 | 사용자 불가, Edge Function(service role)만 | 본인 행만 |
| `uploads` 버킷 | 본인 폴더(`{user_id}/`)만 | 본인 폴더에만 | 불가 | 본인 폴더 + Edge Function |

# 13. Technical Stack

| 도구·기술 | 역할 |
|---|---|
| **Lovable** | 화면 디자인 초안과 프론트엔드 초기 코드 생성 |
| **Figma** | 디자인 참고·수정이 필요할 때 화면 시안 정리 (선택) |
| **GitHub** | 코드 저장소, Lovable 코드 동기화, 배포 연동 |
| **VS Code + Claude Code** | 로컬 개발, Edge Function·DB 설정 작성, 디버깅 |
| **Supabase** | 인증(Auth), 데이터베이스(Postgres + RLS), 파일 저장(Storage), 서버 코드(Edge Functions), API Key 보관(Secrets) |
| **Claude API** | 공고 판정(Claude Haiku 5.5), 적합도 분석(Claude Sonnet 5.5) |

### 구성

- **프론트엔드**: React + Vite + TypeScript + Tailwind CSS + shadcn/ui (Lovable 기본 구성)
- **백엔드**: 별도 서버 없이 Supabase Edge Functions(Deno) 2개
  - `fetch-job-posting`: URL 읽기 → 본문 추출 → Haiku로 공고 판정·요약
  - `analyze-match`: Storage에서 파일 읽기 → Sonnet 분석 → JSON 검증 → DB 저장 → 파일 삭제
- **데이터베이스**: Supabase Postgres, `analyses` 테이블 1개 + RLS
- **인증**: Supabase Auth 이메일·비밀번호. 브라우저는 로그인 토큰을 붙여 Edge Function을 호출하고, Edge Function은 토큰으로 사용자를 확인합니다.

### AI 연동 방식

- 이력서 PDF와 캡처 이미지는 별도 글자 추출 도구 없이 Claude API에 직접 보냅니다. Claude API는 PDF와 이미지(JPEG·PNG·GIF·WebP) 입력을 지원합니다.
- 공식 문서 기준 제한(2026-10-20 확인)과 이 서비스의 제한은 다음과 같습니다.

| 항목 | Claude API 제한 | 이 서비스의 제한 |
|---|---|---|
| 요청 1회 전체 크기 | 32MB | PDF 5MB + 캡처 3MB × 5장 = 최대 20MB. base64로 바꾸면 약 1.33배라서 약 27MB로 제한 안에 들어옴 |
| PDF 페이지 수 | 100페이지 (1M 토큰 미만 컨텍스트 기준) | 10페이지 |
| PDF 암호 | 암호·암호화된 PDF 불가 | 업로드 단계에서 거부 |
| 이미지 1장 크기 | 10MB (base64 기준) | 3MB |
| 이미지 개수 | 20장 초과 시 더 엄격한 해상도 제한 적용 | 최대 5장 |

- 응답 형식은 JSON 스키마로 고정하고, 서버에서 한 번 더 검증합니다.
- 공고 판정처럼 단순한 작업은 저렴하고 빠른 Haiku를, 핵심 분석은 Sonnet을 사용해 비용과 품질의 균형을 맞춥니다.

### 개발·배포 워크플로우

1. Lovable로 S1~S5 화면 초안 생성 → GitHub 저장소와 동기화
2. 로컬(VS Code + Claude Code)에서 Supabase 테이블·RLS·Storage 정책 작성
3. Edge Function 2개 작성 → Supabase CLI로 배포, Claude API Key는 Secret으로 등록
4. 프론트엔드와 Edge Function 연결, 10장 체크리스트로 검증
5. 프론트엔드 배포: Vercel에 GitHub 저장소를 연결해 자동 배포 (가정: 배포 플랫폼은 교육 과정 안내에 따라 변경 가능)

### 확인이 필요한 사항

- Supabase Edge Function의 최대 실행 시간과 요청 크기 제한. AI 분석이 최대 90초 걸릴 수 있으므로, 사용하는 요금제 기준으로 확인이 필요합니다.
- 주요 채용 사이트(원티드, 사람인, 잡코리아, 링크드인 등)에서 링크 읽기가 실제로 성공하는지. 개발 초기에 직접 테스트해 캡처 흐름이 얼마나 자주 쓰일지 파악합니다.
